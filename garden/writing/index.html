写文章与随想

长文与随想的 Front Matter 字段、代码块对比、提示框、公式与流程图，以及配图、来源胶囊和链接卡片的入口。

Garden 的内容分为两类：长文（放在 content/posts/）和随想（放在 content/thoughts/）。两者都使用 UTF-8 编码的 Markdown 文件，文件名只能包含小写字母、数字和连字符（a-z、0-9、-）。

1.长文 Front Matter（content/posts/*.md）

用 make new DIR=systems SLUG=wal-checkpoint TITLE="深入理解 WAL丨检查点与恢复流程" 创建文章，或者手动新建 .md 文件：

---
title: 深入理解 WAL丨检查点与恢复流程
date: 2026-10-18
updated: 2026-10-19
description: 拆解预写日志在并发读写下的页面可见性规则，以及后台检查点如何控制日志文件体积。
tags:
  - 数据库
  - 存储
pinned: false
draft: false
cover: windowsill-herbs.svg
original: https://example.com/original-post
references:
  - title: SQLite Write-Ahead Logging
    url: https://www.sqlite.org/wal.html
  - title: 《Database Internals》
---
字段必填类型说明
title是字符串文章标题。中间写 丨、｜ 或 | 会分成两行并按字数缩放字号
date是日期字符串发布日期（如 2026-10-18 或带时区的 ISO 时间）
description是字符串文章摘要，显示在正文开头导语、列表页与搜索引擎摘要中
updated否日期字符串最后更新日期，显示在文章元信息栏并用于 RSS 排序
publishAt否日期字符串定时发布时间；早于当前构建时间（或设置 CONTENT_INCLUDE_DRAFTS=1）才会发布
tags否字符串数组文章标签列表，点击标签会跳转到 /blog?t=<标签> 筛选
pinned否布尔值设为 true 时显示在站点首页「置顶」区域
draft否布尔值设为 true 时视为草稿，正式构建会自动跳过
cover否路径字符串封面图路径，相对 content/covers/ 目录
original否完整链接原文链接，设置后在标题下方元信息栏显示 原文 ↗
references否{ title, url? }[]文末参考资料列表，构建期自动提取域名并渲染在正文底部的「参考」卡片中

文章页底部，在「来自开放网络的回应」和评论之间，有「上一篇」「下一篇」两个按钮。长文只和长文排，按 date 先后，上一篇是更早的那篇；专栏文章按专栏里的顺序排；最早或最新的一篇只显示一侧。

注意

不要在 Front Matter 里手写 slug 字段（npx garden check 会报 unexpected-slug 错误：不要写 slug，文件名就是标识）。文章也没有 topic 分类字段。

2.代码块与「代码 / 对比上一版」切换

普通代码块在右上角带有语言名称（如 RUST、TS、PYTHON、SHELL）和复制按钮。想展示一段代码和上一版相比改了什么，先放改好的完整代码，再紧跟着写一个 garden 想法块，用一句话写出改动内容：

```go
func openStore(path string) (*Store, error) {
	return openWithMode(path, ModeWAL)
}
```

```garden
和上一版比：打开存储时的模式从 ModeJournal 改成了 ModeWAL。
```

Agent 按 garden-ui skill 会通过 npx garden ui apply 把这段想法替换成紧挨着完整代码的 diff 围栏（详见 用 AI 写作）。页面渲染时会把这两段合成一个可切换 「代码」 和 「对比上一版」 的代码框，右上角的复制按钮始终复制新版完整代码：

func openStore(path string) (*Store, error) {
	return openWithMode(path, ModeWAL)
}

 func openStore(path string) (*Store, error) {−	return openWithMode(path, ModeJournal)（删除）+	return openWithMode(path, ModeWAL)（新增） }

手写格式：如果不使用 Agent，也可以直接在完整代码块正下方手写一段 diff 代码块（两段之间只隔空行）：

```diff
 func openStore(path string) (*Store, error) {
-	return openWithMode(path, ModeJournal)
+	return openWithMode(path, ModeWAL)
 }
```

重要

diff 代码块必须紧跟在一段完整代码块后面；如果单独写一段 diff 而前面没有完整代码，npx garden check 会报 diff-orphan 错误。

3.中文加粗、荧光笔高亮与提示框

  • 中文标点旁加粗：内置 remark-cjk-friendly，紧挨中文括号、引号或顿号写 **像「这样」的加粗** 能正常解析，不需要在星号两侧加空格。
  • 荧光笔高亮：用 <u>重点句子</u> 或 <mark>重点句子</mark> 可以给文字加上暖黄色荧光笔底纹，效果如：这一句带有荧光笔下划线底色。
  • 提示框（Callouts）：支持 > [!NOTE]、> [!TIP]、> [!IMPORTANT]、> [!WARNING]、> [!CAUTION]（以及 INFO、SUCCESS、DANGER、FAILURE）。在标记同行末尾写文字可替换默认标题：
> [!WARNING] 升级前先备份数据目录
> 修改页大小后需要重建索引文件，不能直接原地回退。

升级前先备份数据目录

修改页大小后需要重建索引文件，不能直接原地回退。

4.本地图片、来源胶囊与外部链接卡片

这三项写在 Markdown 正文里。渲染规则在组件页，这里只保留文件放哪：

  • 本地图片：长文 content/posts/my-post.md 的配图放在同名目录 content/posts/my-post/，正文用 ./my-post/diagram.svg 引用。图注见本地图片。
  • 来源胶囊与链接卡片不另建文件。见来源胶囊和链接卡片。

5.数学公式与 Mermaid 图表

  • LaTeX 数学公式：使用 KaTeX 在构建与渲染期直接排版。行内公式写 $L = \lambda W$，独立公式块写 $$...$$。公式里带下划线的多字母变量名（如 group_num、max_batch）会自动保护为正体标识符 \mathrm{group\_num}，而 W_q、H_{kv} 等单字母带下标仍保持标准数学下标。

6.写随想（content/thoughts/*.md）

随想适合记录短文字、多张配图、本地音视频或外部网页链接卡片：

---
title: 雨夜调试记录
date: 2026-10-19 21:30
tags:
  - 日常
media:
  - type: image
    src: ./rainy-night/terminal.png
    alt: 终端里的压测输出
  - type: link
    src: https://sqlite.org/wal.html
    title: SQLite Write-Ahead Logging
---

记一段简短的想法，支持完整的 Markdown 语法。

media 数组支持四类条目：image（多张图片自动拼成宫格图集）、audio（原生 <audio> 音频播放器）、video（原生 <video> 视频播放器，指向视频文件地址，可配 poster 封面）和 link（用你写的 src、title、description、image 做一张链接卡）。正文里的链接卡片见链接卡片。
