GARDEN / 博客框架

一个基于 Markdown 的个人博客框架。

Garden 是公开的博客框架，不是你的内容仓库。使用模板后，你只在自己的源码仓库里维护 Markdown；推送后，GitHub Actions 会把它生成并发布为公开博客。

FLOW / 职责划分

你只需要维护源码仓库

日常写作从源码仓库开始，也在源码仓库结束。框架提供能力，Actions 负责构建，Pages 只负责展示；管理后台和评论都是可选补充。

Garden 模板你的源码仓库GitHub Actions公开博客
01

Garden 框架

公开模板和上游代码，负责内容模型、页面生成与发布工作流。使用模板后，不需要在这里保存个人文章。

02

源码仓库

文章、随想、专栏、配置和草稿的唯一真源。你直接编辑这里，管理后台也只向这里提交内容。

03

公开博客

GitHub Actions 从源码生成静态文件，再交给 GitHub Pages。双仓模式下，公开产物仓库只保存生成结果，不手工修改。

04

可选服务

管理后台补充随想发布和媒体上传；Giscus 评论可以使用独立公开仓库。它们都不会替代源码仓库。

CONTENT / 内容

博文、随想和专栏

先选择内容类型，再编辑对应文件。三种内容都保存在源码仓库中，直接编辑文件即可完成全部公开内容的维护和发布。

01 / 博文

写一篇文章

博文保存在 content/posts/ 中，可以按照主题建立任意层级的子目录。文件路径同时决定文章地址，正文仍然是普通 Markdown。

  1. 1在 content/posts/ 中创建一个 .md 文件。
  2. 2在 Front Matter 中填写标题、日期、摘要、主题、标签和封面。
  3. 3使用 Markdown 编写正文，图片和其他附件可以使用相对路径。
  • GFM 表格、任务列表与脚注
  • TypeScript、Go、Rust 等代码高亮
  • 数学公式与 Mermaid 图表
  • 图片、音视频与平台嵌入
  • 草稿、定时发布与置顶
  • 文章目录、上一篇与下一篇
发布后

构建时会生成文章页面，并把标题、摘要和正文加入博文列表、主题归档、全文搜索与 RSS。

content/posts/writing/first-post.md
---
title: 我的第一篇文章
slug: first-post
date: 2026-08-03T09:00:00+08:00
description: 这篇文章记录我为什么重新开始写博客。
topic: 写作
tags: [Markdown, 博客]
pinned: false
cover: ./assets/cover.jpg
---

正文从这里开始。

## 一个小标题

可以继续插入图片、代码、公式和 Mermaid 图表。

02 / 随想

发布一条随想

随想适合记录几句话、一个链接或一组多媒体。它同样保存在 Git 仓库中，只需要更少的字段，也可以通过可选管理后台发布。

  1. 1直接创建 content/thoughts/<slug>.md，或者在管理后台填写内容。
  2. 2填写标题、唯一 slug 和日期；需要暂存时加入草稿状态。
  3. 3在 media 中按顺序添加图片、音频、视频或外部链接。
  • 纯文字短内容
  • 多张图片与混合图集
  • 音频和视频
  • 带标题的外部链接
  • 草稿与公开状态
  • 独立永久链接
发布后

发布后的内容会出现在随想时间线和首页最近随想中，每条随想都有可以单独分享的永久链接。

content/thoughts/walk-after-rain.md
---
title: 雨后的散步
slug: walk-after-rain
date: 2026-08-03T18:30:00+08:00
tags: [生活]
media:
  - type: image
    src: ./assets/street.jpg
    alt: 雨后的街道
  - type: audio
    src: ./assets/rain.mp3
    title: 雨声
---

今天下班后多走了两公里。

03 / 专栏

创建一个专栏

专栏不复制文章，而是在 content/columns.yaml 中引用已经存在的博文。posts 的排列顺序就是专栏的阅读顺序。

  1. 1在 content/columns.yaml 中添加专栏名称、介绍、状态和封面。
  2. 2在 posts 中填写博文相对 content/posts/ 的路径。
  3. 3按照希望读者阅读的顺序排列路径；同一篇文章可以加入多个专栏。
  • 专栏标题、说明和状态
  • 独立专栏封面
  • 文章顺序可控
  • 复用同一份 Markdown
  • 一篇文章加入多个专栏
  • 系列文章导航
发布后

构建后会生成独立专栏页面。读者可以按照配置顺序浏览文章，文章页也会显示它所属的系列与前后篇目。

content/columns.yaml
columns:
  - slug: writing-system
    title: 写作系统
    description: 记录从选题到发布的完整写作过程。
    status: 持续更新
    cover: /images/columns/writing-system.webp
    coverAlt: 桌面上的笔记本与钢笔
    posts:
      - writing/why-write
      - writing/collect-material
      - writing/revise-and-publish

EMBEDS / 高级嵌入

文章不只能放文字。

本地图片、音频和视频继续使用标准 Markdown / HTML；外部平台统一使用 embed 代码块。可播放的平台直接播放，受平台限制的内容自动退化为摘要卡片。

  • 01
    YouTube / Bilibili

    识别普通分享链接，自动转换成响应式播放器，并保留原站入口。

  • 02
    X / Twitter

    以带平台标识的摘要卡片展示，避免依赖容易失效的第三方脚本。

  • 03
    微信公众号

    保留标题、摘要和原文链接；微信禁止稳定 iframe 时仍有完整降级体验。

  • 04
    其他网站

    手动提供标题、摘要与封面，生成不依赖远端抓取的网页预览卡片。

content/posts/example.mdMarkdown
```embed
url: https://www.youtube.com/watch?v=VIDEO_ID
title: 这段视频讲了什么
description: 给读者一个值得点开的理由。
image: https://example.com/cover.jpg
```
为什么不自动抓网页摘要？

构建阶段主动抓取任意 URL 会带来 SSRF、超时和内容漂移风险。Garden 选择显式填写摘要：发布结果可预测，原站失效时文章也仍然可读。

SYSTEM / 系统能力

Markdown、搜索与自动发布

写作者只维护 Markdown、附件和专栏配置。页面生成、搜索索引和订阅文件由构建脚本统一处理。

01

Markdown 与多媒体

兼容 Typora 常用写法，支持 GFM、代码高亮、数学公式、Mermaid，以及图片、音视频、平台嵌入和网页摘要。

02

阅读与内容发现

自动生成文章目录、阅读时长、字数、前后篇导航、主题归档和全文搜索，搜索结果会高亮命中内容。

03

发布与订阅

推送到 main 后由 GitHub Actions 构建并发布到 GitHub Pages，同时生成 RSS、sitemap、robots 和 Open Graph 元数据。

04

开放集成

需要时可以接入 Giscus 评论、Webmention、无 Cookie 统计和对象存储；不配置这些服务也能正常写作和发布。

ADMIN / 管理后台

管理后台能做什么

后台是一个可选的独立服务，处理需要登录和服务端密钥的工作。公开博客仍然是静态站点，内容仍然保存在 Git 仓库中。

01

发布和管理随想

新建随想、保存草稿、正式发布、撤回或删除。每次修改都会写回 content/thoughts/，不会另存一份数据库副本。

02

上传多媒体

图片、音频和视频可以直接上传到阿里云 OSS，随想中只保存公开地址，避免把大文件塞进 Git 历史。

03

管理博文置顶

后台可以切换博文的首页置顶状态，并查看博文所属专栏。正文仍然使用 Markdown 编辑，专栏顺序仍由 columns.yaml 管理。

04

分发到其他平台

可以直接发布到 X，或调用自建服务同步到 CSDN、知乎和掘金；没有配置接口时，也能复制标题、栏目和公开链接。

后台的边界

它不是一套完整 CMS。长文章继续在 Typora 或其他 Markdown 编辑器中编写，专栏继续在 content/columns.yaml 中编排；后台主要补上随想发布、媒体上传、博文置顶和内容分发。

  1. 01GitHub 登录

    只允许白名单中的账号进入后台。

  2. 02执行内容操作

    发布随想、上传附件、置顶或分发博文。

  3. 03提交到内容仓库

    后台使用服务端令牌修改 Markdown。

  4. 04自动更新博客

    main 分支变更后由 Actions 重新发布。

ENABLE / 启用后台

单独部署，再连接内容仓库

  1. 把同一份 Garden 部署到 Node、Docker 或 Cloudflare Workers。
  2. 配置 GitHub OAuth、允许登录的账号，以及仅能写入内容仓库的令牌。
  3. 需要上传附件或跨平台分发时，再配置 OSS 和各平台接口。
ADMIN_URL=https://admin.example.com
CONTENT_REPOSITORY=owner/repository
CONTENT_BRANCH=main
ADMIN_GITHUB_LOGINS=your-github-login

# 令牌与密钥只保存在后台服务中
CONTENT_GITHUB_TOKEN=github_pat_xxx
GITHUB_OAUTH_CLIENT_ID=Ov23li_xxx

SETUP / 安装与配置

从模板到公开博客

公开博客不需要数据库和服务器。创建仓库、替换配置与内容，再推送到 main，GitHub Actions 就会完成构建和发布。

01

创建自己的仓库

使用 GitHub 的 Use this template，推荐将仓库命名为 <owner>.github.io。源码可以直接公开，也可以在 GitHub Free 下放进私有仓库，再把生成文件发布到公开 Pages 仓库。

02

在本地启动

make dev

第一次运行会自动安装依赖并创建本地配置，随后启动预览。浏览器打开终端显示的地址即可。

03

替换配置与内容

site.config.yaml
站点名称、作者资料和各页面标题
content/posts/
长文章与附件
content/thoughts/
随想 Markdown
content/columns.yaml
专栏资料与文章顺序
04

提交并发布

make update

命令会先完成检查，再提交并推送源码仓库。main 分支更新后，Actions 自动生成页面、搜索索引、RSS 和 sitemap。

两种部署方式

公开源码使用单仓即可；需要隐藏草稿时，把源码放进私有仓库，并配置 PAGES_REPOSITORY指向公开产物仓库。两种方式都只运行 make update。

草稿预览

本地使用 CONTENT_INCLUDE_DRAFTS=1 make dev，即可预览草稿和未来定时文章。

可选服务

评论、Webmention、统计和管理后台按需配置；任何密钥都只放在部署平台的 Secret 中。
