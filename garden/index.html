博文

写一篇文章

文件放在 content/posts/。路径就是网址，正文是普通 Markdown。可以按主题分子目录。

  1. 在 content/posts/ 里新建一个 .md 文件。
  2. 开头写下标题、日期、摘要、主题和标签。封面可有可无。
  3. 接着写正文。图片用相对路径，和文件放在一起。

推送后，这篇文章会出现在列表、主题、搜索和 RSS 里。

content/posts/writing/first-post.md
---
title: 我的第一篇文章
date: 2026-08-03 09:00:00
description: 这篇文章记录我为什么重新开始写博客。
topic: 写作
tags: [Markdown, 博客]
pinned: false
cover: writing/first-post.jpg
---

正文从这里开始。

## 一个小标题

可以继续插入图片、代码、公式和 Mermaid 图表。

随想

写一条随想

几句话、一张图或一个链接。字段更少。也可以在后台写，写完同样进仓库。

  1. 新建 content/thoughts/文件名.md，或在后台填写。
  2. 文件名就是地址。标题和日期写在开头。先存着就标成草稿。
  3. 图片、音频、视频和链接按顺序放进 media。

它会出现在随想页和首页，并且有自己的链接。

content/thoughts/walk-after-rain.md
---
title: 雨后的散步
date: 2026-08-03 18:30:00
tags: [生活]
media:
  - type: image
    src: ./assets/street.jpg
    alt: 雨后的街道
  - type: audio
    src: ./assets/rain.mp3
    title: 雨声
---

今天下班后多走了两公里。

专栏

把文章收成专栏

专栏不复制文章。它只是 content/columns.yaml 里的一份阅读顺序。

  1. 在 content/columns.yaml 里写名称、介绍和封面。
  2. 在 posts 里填文章相对 content/posts/ 的路径。
  3. 按你希望读者阅读的顺序排列。同一篇可以进多个专栏。

读者按这个顺序读。文章页也会显示它属于哪一组，以及上一篇、下一篇。

content/columns.yaml
columns:
  - slug: writing-system
    title: 写作系统
    description: 记录从选题到发布的完整写作过程。
    status: 持续更新
    cover: /images/columns/writing-system.webp
    coverAlt: 桌面上的笔记本与钢笔
    posts:
      - writing/why-write
      - writing/collect-material
      - writing/revise-and-publish

跑起来

不需要数据库。换上你的名字和第一篇文章，推送即可。

  1. 1

    创建站点

    运行 npx hd-garden init my-blog。目录里留下 content/ 和 site.config.yaml。仓库名叫 <owner>.github.io 时，地址最直接。

  2. 2

    在本地看

    make dev

    第一次会安装依赖。然后打开终端里的地址。

  3. 3

    换成你的内容

    site.config.yaml
    站名、作者、各页标题
    content/posts/
    长文和附件
    content/thoughts/
    随想
    content/columns.yaml
    专栏和阅读顺序
  4. 4

    发布

    make update

    先检查，再提交并推送。main 更新后，网站、搜索和 RSS 会重新生成。

仓库可以是私有的。公开仓库一种就够。想把草稿留在私有仓库时，用 PAGES_REPOSITORY 指向公开的页面仓库。两种都是 make update。

先看草稿。CONTENT_INCLUDE_DRAFTS=1 make dev 会把草稿和还没到时间的文章也显示出来。

密钥不进仓库。评论、统计和后台的密钥放在部署平台。

视频和链接

自己的图片、音频和视频用 Markdown。别人的页面用 embed 围栏。能播的直接播，不能播的显示成一张卡片。

content/posts/example.md
```embed
url: https://www.youtube.com/watch?v=VIDEO_ID
title: 这段视频讲了什么
description: 给读者一个值得点开的理由。
image: https://example.com/cover.jpg
```
  • YouTube / Bilibili

    贴上分享链接，页面里就能播放，也能回到原站。

  • X / Twitter

    显示成一张带出处的卡片，不依赖对方的脚本。

  • 微信公众号

    留下标题、摘要和原文链接。微信不允许嵌进页面时，卡片仍然能点开。

  • 其他网站

    自己写标题、摘要和封面。不在构建时去抓那个网址。

摘要写在文章里。构建时不去抓任意网址。原站打不开，文章还在。需要时用 make embed URL=... 拉一次，看过再贴进去。

推送之后

你的仓库，到 GitHub 构建，再到公开网站。

框架画页面。你的文章不放在框架仓库里，而在你自己的内容仓库。读者打开的是生成出来的静态页。

同一次构建会带上正文、目录、前后篇、搜索、RSS 和 sitemap。后台和评论都可以以后再加，不接也能发布。

后台

长文继续在编辑器里写。后台只做需要登录的事：随想、附件、置顶、转发，以及文章里的交互。

写随想

保存草稿，或直接发布。文件写回 content/thoughts/，没有另一份数据库。

上传附件

图片、音频和视频可以传到对象存储。文章里只留下地址。

置顶

让一篇博文出现在首页前面。正文还是在编辑器里改。

发到别处

可以发到 X，或同步到 CSDN、知乎、掘金。没配接口时，复制标题和链接。

改文章里的交互

写作台把一句话收成可交互的块。组件页能看到每一种块长什么样。

它不是整套编辑器

长文仍用 Typora 或其他 Markdown 编辑器。专栏顺序仍在 content/columns.yaml 里排。

  1. 1用 GitHub 登录

    只有名单里的账号能进来。

  2. 2做一件事

    写随想、上传、置顶，或发到别处。

  3. 3写回仓库

    后台把改动提交到你的内容仓库。

  4. 4网站更新

    main 变了之后，页面会重新发布。

想用后台，再单独部署一份

  1. 把同一份 Garden 部署到 Node、Docker 或 Cloudflare Workers。
  2. 配好 GitHub 登录、允许的账号，以及只能改内容仓库的令牌。
  3. 要上传附件或转发到其他网站时，再配存储和各平台接口。
ADMIN_URL=https://admin.example.com
CONTENT_REPOSITORY=owner/repository
CONTENT_BRANCH=main
ADMIN_GITHUB_LOGINS=your-github-login

# 令牌只放在后台服务里
CONTENT_GITHUB_TOKEN=github_pat_xxx
GITHUB_OAUTH_CLIENT_ID=Ov23li_xxx
