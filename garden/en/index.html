Garden Handbook/Overview

Write in Markdown | Push to Update the Site

Write posts, short notes, and columns in Markdown inside your own Git repository.

Garden is a Claude-style blog framework where you write posts in Markdown and describe components in plain language.

A Complete Example

The four steps in this section come from a real post, and every command output is taken verbatim from an actual run.

1. The Author Writes an Idea

Drop an unnamed garden fence where the interactive block should go and state what the reader adjusts and sees:

## Writing Pace

```garden compose
Let the reader drag daily word count and writing days per week to see how many weeks an 8,000-word article takes.
```

2. The Agent Scans and Writes Back the Component

Tell the Agent to compile content/posts/writing-pace.md. Following the garden-compose skill in the repository, the Agent first runs npx garden ui scan to read the line number, original wording, and hash:

$ npx garden ui scan content/posts/writing-pace.md
{
  "file": "content/posts/writing-pace.md",
  "draft": false,
  "blocks": [
    {
      "lang": "garden-compose",
      "status": "uncompiled",
      "startLine": 9,
      "intentHash": "8866427a",
      "intent": "Let the reader drag daily word count and writing days per week to see how many weeks an 8,000-word article takes.",
      "section": "Writing Pace"
    }
  ]
}

Next, the Agent reads the component catalog from npx garden ui prompt, writes a garden compose block, and runs npx garden ui apply with --intent-hash to replace only that fence while leaving the rest of the file byte-for-byte untouched:

$ npx garden ui apply content/posts/writing-pace.md --intent-hash 8866427a --file new.md
{"ok":true,"file":"content/posts/writing-pace.md","kind":"garden","line":9}

3. The Pre-commit Hook Checks and Points to the Project Skill

On the first garden sync or garden dev run, Garden writes exec npx --no-install garden ui check --staged --quiet to .git/hooks/pre-commit. If the author commits before step 2, the hook blocks the commit and shows diagnostics and a short project-skill instruction:

$ git commit -m "Writing pace"
content/posts/writing-pace.md:9  -  compose-uncompiled  uncompiled compose idea remaining
Use garden-compose skill (.agents/skills/garden-compose/SKILL.md), fix the failing blocks, then recheck.

The terminal shows diagnostics and a short instruction to load the project garden-compose skill. No file, clipboard copy, source dump, or catalog export is produced by default. After repair, the hook exits silently with code 0.

4. The Rendered Result

The garden compose fence written back in step 2 renders directly on the article page as an interactive calculator:

Humans and Agents Share the Same Tools

The npx garden ui scan, npx garden ui apply, and npx garden ui check commands used by the Agent are the exact commands run by the author's pre-commit hook. When the hook stops a commit, its output is the instruction for the Agent's next step. See Writing with AI.

The remaining sections cover the layout and component rules that work out of the box without an Agent.

Two-line Titles and the 740px Reading Column

Write | (with spaces on both sides) inside a title to split it across two lines and scale the font size to fit the longer line. Body copy stays inside a 740px column, while wide figures expand symmetrically into the side margins without overlapping the navigation or table of contents.

Code Blocks and the Diff Toggle

Write a one-sentence garden idea right below an updated code block to describe what changed, and the Agent generates the adjacent diff fence; you can also write the diff fence by hand. When a code block is immediately followed by a diff block, the page combines them into a single frame with tabs for the full code and the diff against the previous version, while the copy button always copies the new code.

pages:
  garden:
    title: "Write in Markdown | Push to Update the Site"
    subtitle: "Write posts, short notes, and columns in Markdown inside your own Git repository."

 pages:   garden:−    title: "Write in Markdown.\nPush to update the site." (removed)−    subtitle: "" (removed)+    title: "Write in Markdown | Push to Update the Site" (added)+    subtitle: "Write posts, short notes, and columns in Markdown inside your own Git repository." (added)

Note

A diff fence must sit immediately after a complete code block; a standalone diff fence triggers a diff-orphan error in npx garden check.

Custom Callout Titles

Write text on the same line after > [!TIP] (or place a bold line immediately below) to replace the default callout title. Supported types include NOTE, TIP, IMPORTANT, WARNING, and CAUTION.

From Init to Daily Writing

Your site repository stores only configuration, Markdown posts, and static assets, while hd-garden provides the renderer and build scripts. Initialize and preview a site locally:

npx hd-garden init my-blog
cd my-blog
npm install
make dev

Run make update when a post is ready; it runs the full check and build before committing and pushing. Read the chapters for details:

  • Quick Start: Directory layout, creating posts with make new, previewing drafts, and daily commands.
  • Writing with AI and Checks & Shortcuts: Insert an idea, preview the component, and open the catalog in VS Code, Cursor, or Typora, and install the plugins with npx garden editors install.
  • Site & Column Config: Every field in site.config.yaml, custom SVG icons, and ordering series in content/columns.yaml.
  • Deploy to GitHub Pages: A single GitHub Actions workflow that supports both one public repository and a private source repo paired with a public Pages repo.
  • Writing Posts and How the Reading Layout Works: Front Matter fields, three-tier adaptive widths, and color tokens. Link cards, source chips, and local images are on Components Overview.
